# CoriseDND

Конструктор персонажей для настольных ролевых игр в сеттинге Corise.
Учебный проект: серверная часть (Kotlin, Ktor, PostgreSQL) и Android-приложение (Kotlin, Jetpack Compose).

## Состав

| Часть | Проект | Стек |
| --- | --- | --- |
| Сервер | `corise-server` | Ktor 3.0.3, Exposed 0.57.0, Flyway 10.21, HikariCP, PostgreSQL, BCrypt, JWT, Swagger |
| Клиент | `CoriseDND` (Android Studio) | Kotlin, Jetpack Compose, MVVM, Retrofit, DataStore, Navigation Compose, multiplatform-markdown-renderer |

## Возможности

- Регистрация и вход (пароль хранится в виде BCrypt-хеша, токен JWT живёт 60 минут).
- Список персонажей: поиск, фильтр по расе, сортировка, постраничная подгрузка.
- Создание персонажа по правилам системы: мастер из 5 шагов (основное, характер и биография, атрибуты, навыки, заклинания).
- Просмотр, изменение и удаление персонажа.
- Заклинания персонажа, инвентарь и экипировка (оружие, броня, щит).
- Атрибуты (7) и навыки (46): при создании очки распределяются по правилам (point buy), после создания значения от 0 до 10 меняются на экране правки.
- Блок характера и биография персонажа.
- Языки: язык культуры персонаж знает по умолчанию.
- Расчётные значения: максимум здоровья (HP) и магической нагрузки (ML) считает сервер.
- Справочник: расы, культуры, религии, предыстории, классы, оружие, броня и щиты, заклинания, лор (статьи в формате Markdown).
- Свой контент: пользователь создаёт, изменяет и удаляет собственные расы, культуры, религии, предыстории, классы, заклинания, оружие и броню. Стандартный контент виден всем и доступен только для чтения, пользовательский виден только автору.

## Требования

- JDK 21
- PostgreSQL (проверено на 18)
- Android Studio (клиент), эмулятор или телефон с Android 11+ (minSdk 30)

## Сервер

### 1. База данных

Создайте пользователя и две базы: рабочую и тестовую.

```sql
CREATE USER corise WITH PASSWORD 'ваш_пароль';
CREATE DATABASE corise OWNER corise;
CREATE DATABASE corise_test OWNER corise;
```

Начиная с PostgreSQL 15 обычный пользователь не может создавать таблицы в чужой базе. Поэтому владельцем баз должен быть пользователь приложения (как выше). Если базы уже созданы под `postgres`:

```sql
ALTER DATABASE corise OWNER TO corise;
ALTER DATABASE corise_test OWNER TO corise;
-- затем подключитесь к каждой базе и выполните:
GRANT ALL ON SCHEMA public TO corise;
```

Таблицы вручную создавать не нужно: схему накатывает Flyway при старте.

### 2. Настройки

Скопируйте `.env.example` в `.env` и заполните значения:

| Переменная | Описание |
| --- | --- |
| `DB_URL` | адрес базы, например `jdbc:postgresql://localhost:5432/corise` |
| `DB_USER`, `DB_PASSWORD` | пользователь и пароль базы |
| `JWT_SECRET` | секрет подписи токенов, не короче 32 символов (например, `openssl rand -base64 48`) |
| `JWT_ISSUER`, `JWT_AUDIENCE` | издатель и аудитория токена |
| `JWT_EXPIRES_MINUTES` | срок жизни токена в минутах (по умолчанию 60) |
| `PORT` | порт сервера (по умолчанию 8080) |

Файл `.env` не попадает в git. Переменные окружения имеют приоритет над `.env`.

### 3. Запуск

Запустите `Main.kt` (`com.corise.dnd.MainKt`) из IDE или командой:

```
gradlew run
```

При первом старте Flyway сам накатит все миграции на пустую базу.
Документация API (Swagger): http://localhost:8080/swagger

### Миграции

| Миграция | Что делает |
| --- | --- |
| V1 | основная схема (35 таблиц), ограничения и внешние ключи |
| V2 | заметки, автор (`created_by`) у рас, классов, заклинаний, предметов |
| V3 | стартовые данные (временные) |
| V4 | `created_by` у остальных таблиц с `is_custom`, уникальность имён |
| V5 | слот щита у персонажа, хват оружия |
| V6 | настоящие атрибуты (7, с описаниями) и навыки (46), колонка `attribute.description` |
| V7 | настоящие расы (7) и древа наследия (70 узлов) |
| V8 | настоящие культуры (9) |
| V9 | настоящие религии (9) |
| V10 | настоящие предыстории (4) |
| V11 | языки (8) и языки культур |

Файлы лежат в `src/main/resources/db/migration`. Уже применённые миграции не редактируются: изменения оформляются новой миграцией.

Миграции V6-V10 заменяют временные данные V3 настоящими. Совпавшие по названию записи обновляются, остальные временные удаляются; если на запись уже ссылается персонаж, она остаётся (в журнале Flyway появляется сообщение). Заклинания, оружие и броня пока остаются временными, классов в базе нет (в системе нет готовых данных).

### Архитектура

Запрос проходит путь Router → Service → Repository → БД.

- `routes/`: только HTTP, идентификатор пользователя берётся из проверенного токена
- `service/`: бизнес-правила, валидация, транзакции; `Stats.kt` содержит расчёт характеристик и правила создания
- `repository/`: доступ к данным
- `model/`: таблицы и ORM-сущности
- `dto/`: схемы запросов и ответов (ORM-сущности наружу не отдаются)
- `database/`, `config/`, `security/`: подключение и миграции, настройки, JWT

Ошибки возвращаются в едином формате `{code, message, details}`. Внутренние детали (трассировки, SQL) клиенту не отдаются, а пишутся в лог.

### API

Все маршруты имеют префикс `/api/v1`, кроме регистрации и входа они требуют заголовок `Authorization: Bearer <токен>`. Полное описание схем и кодов ответов есть в Swagger.

| Маршрут | Описание |
| --- | --- |
| `POST /auth/register`, `POST /auth/login`, `GET /me` | регистрация, вход, текущий пользователь |
| `GET /races`, `/cultures`, `/religions`, `/backstories`, `/classes`, `/weapons`, `/armours`, `/skills`, `/attributes` | справочники (стандартный и собственный контент) |
| `GET /spells` | заклинания: `search`, `type`, `limit`, `offset` |
| `GET /lore`, `GET /lore/{id}` | лор: список (`search`, `category`, `limit`, `offset`) и статья в Markdown |
| `POST /{ресурс}`, `GET`, `PUT`, `DELETE /{ресурс}/{id}` | собственный контент: расы, культуры, религии, предыстории, классы, заклинания, оружие, броня |
| `GET /characters` | мои персонажи: `search`, `raceId`, `sort` (`name`, `level`, `id`), `order`, `limit`, `offset` |
| `POST /characters`, `GET`, `PUT`, `DELETE /characters/{id}` | создание, просмотр, изменение, удаление персонажа |
| `POST /characters/{id}/spells`, `DELETE /characters/{id}/spells/{spellId}` | заклинания персонажа |
| `PUT`, `DELETE /characters/{id}/items/{itemId}` | инвентарь |
| `PUT /characters/{id}/equipment` | экипировка: оружие, броня, щит |
| `PUT /characters/{id}/attributes/{attributeId}`, `PUT /characters/{id}/skills/{skillId}` | значение атрибута и уровень навыка (0-10) |
| `PUT /characters/{id}/personality` | блок характера и биография |

Формат страницы: `{items, total, limit, offset, hasMore}`.

### Правила системы

**Создание персонажа** (`POST /characters`): сервер проверяет point buy и отклоняет нарушения кодом 422. Всё создаётся в одной транзакции.

- Атрибуты: 27 очков, значение каждого от 0 до 5, повышение с уровня n на n+1 стоит n+1 очков (итого уровень v стоит v(v+1)/2).
- Навыки: 35 очков, значение каждого от 0 до 5, уровень стоит 1 очко.
- Язык культуры записывается персонажу автоматически, блок характера сохраняется вместе с персонажем.
- Текущее HP при создании равно максимальному, текущая нагрузка равна 0.

**Расчётные значения** (сервер отдаёт `hpMax` и `mlMax`, в базе хранится только текущее значение):

- Максимум HP = 10 + бонус Выносливости + уровень × 2. Бонус Выносливости: очки 1-5 дают по +1 HP, очки 6-10 по +2 HP.
- Максимум ML = (уровень + модификатор навыка «Магическая Стойкость» + Выносливость) × 10. Модификатор навыка равен уровню навыка, делённому на 2 с округлением вниз.
- Бонусы расы, класса и других источников к характеристикам пока не считаются, значения вводятся вручную.

**Экипировка:** три слота (оружие, броня, щит), надеть можно только предмет из инвентаря. Щит нельзя использовать с двуручным или древковым оружием (422).

**Свой контент:** стандартный контент виден всем и доступен только для чтения, пользовательский виден и изменяем только автором. Чужой пользовательский контент для остальных не существует (404).

### Коды ответов

| Код | Когда |
| --- | --- |
| 200, 201, 204 | успех, создание, удаление |
| 401 | нет токена или токен недействителен |
| 403 | чужой персонаж, изменение стандартного контента |
| 404 | записи нет или это чужой пользовательский контент |
| 409 | дубль, конфликт, запись используется |
| 422 | ошибка валидации |

### Тесты

Автотесты работают с реальным PostgreSQL на отдельной базе `corise_test` (Docker не нужен). Рабочая база в тестах не используется.

1. Создайте базу `corise_test` (см. выше).
2. Пользователь и пароль берутся из `.env`, имя базы подменяется на `corise_test`. Чтобы задать другое, используйте переменные `TEST_DB_URL`, `TEST_DB_USER`, `TEST_DB_PASSWORD`. Имя тестовой базы должно содержать `test`, иначе тесты не запустятся.
3. Запуск из корня проекта `corise-server`:

```
gradlew test
```

Тесты покрывают:

- регистрацию и вход, ошибки входа, доступ без токена;
- создание, получение, изменение и удаление персонажа, ошибки валидации, доступ к чужому персонажу;
- заклинания персонажа, атрибуты и навыки (значения, диапазон 0-10, несуществующий атрибут, чужой персонаж);
- создание по правилам: границы 27 и 35 очков, превышение очков, язык культуры, блок характера;
- расчёт HP и ML (формулы и значения при создании).

Каждый API-тест регистрирует собственного пользователя, поэтому тесты не зависят друг от друга. Количество тестов показывает отчёт Gradle.

## Клиент (Android)

1. Откройте проект в Android Studio и дождитесь синхронизации Gradle.
2. Запустите сервер.
3. Запустите приложение на эмуляторе.

Эмулятор видит компьютер по адресу `10.0.2.2`, поэтому в `data/AppContainer.kt` указано:

```kotlin
const val BASE_URL = "http://10.0.2.2:8080/api/v1/"
```

### Запуск на реальном телефоне

1. Телефон и компьютер в одной Wi-Fi сети.
2. Замените `10.0.2.2` в `BASE_URL` на IP компьютера. Обычный HTTP разрешён в `AndroidManifest.xml` (`android:usesCleartextTraffic="true"`): для учебного проекта это допустимо, для публикации приложения нужен HTTPS.
3. Порт 8080 открыт в брандмауэре, а сервер доступен не только с localhost.

### Экраны

- Вход и регистрация.
- Список персонажей: поиск, фильтр по расе, сортировка, подгрузка при прокрутке.
- Мастер создания персонажа: 5 шагов, на шагах атрибутов и навыков кнопка «Далее» неактивна, пока не потрачены все очки.
- Просмотр персонажа: параметры (HP и ML в виде «текущее / максимум»), характер и биография, атрибуты, навыки, заклинания, экипировка, инвентарь.
- Правка персонажа: основные поля, атрибуты и навыки, блок характера.
- Справочник: разделы, списки с поиском, описания; лор показывается как Markdown.
- Свой контент: создание, изменение и удаление собственных записей справочника.

### Структура

- `data/`: токен (DataStore), Retrofit-интерфейсы, обработка ошибок
- `ui/auth/`: вход и регистрация
- `ui/characters/`: список, просмотр, мастер создания и правка персонажа; `StatWidget.kt` и `PersonalityFields.kt` - общие компоненты атрибутов, навыков и блока характера
- `ui/reference/`: справочник и экраны своего контента, описание разделов (`Section`)
- `ui/AppRoot.kt`: навигация по состоянию токена

## Безопасность

- Пароли хешируются библиотекой BCrypt, своей криптографии нет.
- Токен JWT с ограниченным сроком жизни, передаётся как `Authorization: Bearer <токен>`.
- Токен удалённого пользователя перестаёт работать.
- Ошибка входа всегда одинаковая, по ней нельзя узнать, существует ли email.
- Секреты хранятся только в `.env` (в git не попадает), шаблон: `.env.example`.
